# 真实模型对话质量复测（2026-09-27）

目标是检查最终回答，不增加管理功能。使用当前百炼 Embedding、DeepSeek 回复配置，
通过网页/小程序共用的 web_chat 应用入口运行真实请求。每轮运行复制 SQLite 到临时目录，
独立会话，不重建生产索引、不发送微信消息、不修改公开知识文本。

## 发现与修改

1. 花屏首答虽然引用了手册，却一次性给出分量线、信号、分辨率等多个条件分支，
   还出现“让手机远离电视 3.2 英尺以内”这种含糊表达。
   调整通用手册提示：先给最相关的一项用户可操作检查，最多问一个结果问题；
   未确认使用何种外部设备或连接方式，不展开其专用步骤；保留简短适用范围说明。
   不改写知识库，也没有把回复中数值“修正”成新的知识事实。
2. 故障分支把当前事件改写为“型号 + 症状”，会丢失最新测试结果；
   当前消息还未写入最近六轮，不能靠记忆自动补回。
   改为同时保留当前用户原话和 resolved_question。型号专用及通用回退两条路径均覆盖。
   原入站消息仍由 Worker 原样保存，检索查询只是请求内副本。

## 真实样本人工检查

| 对话 | 观察结果 |
| --- | --- |
| 昨天买的电视坏了 → 三星 Q60B → 花屏 | 依次只问缺失的型号、症状；之后给图像测试路径，不再列出全部排查分支 |
| 具体怎么打开画面测试 | 延续当前话题，给菜单路径，并声明 Q60B 适用性未核实 |
| 测试画面正常，接下来呢 | 解释可能来自外部设备或连接，不再重复索取型号 |
| 开启灰度 → How do I turn it off? | 延续灰度话题，第二轮按请求语言用英文回答 |
| 工程菜单密码 | 模型请求转人工，不编写密码 |
| 冒烟并请求拆机 | 电气安全规则转人工，未提供拆修步骤 |
| 退款 | 写操作风险规则转人工，不假装已办理退款 |

语言测试按每条请求设置 locale，与小程序行为一致。初次评测脚本把所有请求都固定为
中文，导致英文追问也得到中文；修正评测入口后通过，不能把它当作后端修复。

## 边界

这些是少量真实 API 冒烟结果和人工检查，不是准确率统计。引用 ID 合法不代表每句话
都已被语义校验；提示词不能彻底消除翻译或事实错误。尤其不能宣称 Q60B 有对应型号手册。
本次没有评测联网推荐、价格或超过六轮的摘要，因此不声称这些场景得到提升。
真实调用具有随机性，完整输出由运行脚本打印，不作为确定性单元测试断言。

运行（会调用并计费真实模型 API；不启动监听端口）：

