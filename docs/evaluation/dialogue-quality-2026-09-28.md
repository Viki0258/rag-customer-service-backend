# 效果优化：未知型号与故障切换

## 实测发现

真实 API 对话“三星电视花屏了 → 我不知道具体型号，能先排查吗”原先直接进入
`clarification_exhausted`。这里是信息缺失，不等于没有任何可用知识。

## 修改

- Intake 独立提取客户明确提供的品牌，不能从客服角色、推荐产品或无关旧设备推断。
- 已问过型号、品牌为三星、症状明确、存在审核过的通用文档时，进入通用排查。
  不知道型号不再是直接拒答的理由，但不改变型号专属证据要求。
- 通用路径继续使用文档允许列表、原始证据、回复校验及型号适用性提示。
- 通用排查抽取为同一个函数，保留当前原话及补全问题，避免两个入口行为分叉。
- 品牌与型号分开输出后，旧逻辑只检查 model 文本，会漏掉 `brand=Samsung/model=Q60B`。
  复测发现此回归后修复：有独立品牌时以它为准，旧调用无品牌时保留原兼容判断。
  显式非三星品牌不能被旧型号中的 Samsung 覆盖。

## 验证与限制

- 未知型号案例：修改前转人工；修改后给出图像测试路径，追问结果，并说明型号适用性未知。
- 故障切换：最终复测“花屏 → 图像测试正常、现在无声”，能切换到声音自检。
- 边界单元测试覆盖未知品牌、其他品牌、缺少症状、没有通用资料、品牌和型号字段分离、品牌冲突。
- 全量 Python 回归：677 passed、10 skipped；前端测试：5 passed。
- 一次初始实测出现 `intake_unavailable`，仅凭该错误无法区分供应商故障和输出解析问题。
  后续复测未出现，不宣称其根因已修复，也未增加可能掩盖错误的自动重试。
- 均为少量模型冒烟样本，不是准确率提升统计；未测联网推荐或长对话摘要效果。
- 仍通过临时索引副本和隔离会话运行，没有添加知识、部署公网端口或重启用户已停掉的服务。
